# Ручные Тест-Кейсы Браузера — Веб-Интерфейс

> **Для кого:** QA-инженеры, которые проверяют UI/UX вручную в браузере, не скриптами.
> **Как использовать:** После запуска скриптов API проверьте, что браузер отображает результаты ожидаемо.

---

## Предварительные Условия (для всех тестов)

1. **Окружение готово:**
   ```bash
   npm run dev              # в отдельном терминале
   bash scripts/00-preflight.sh
   ```
   
2. **Браузер:** Chrome/Firefox/Safari, дев-консоль открыта (F12)

3. **URL базовый:** `http://localhost:3000`

---

## TC-WEB-01: Корзина — Добавление, Отображение, Удаление

**Что проверяем:** CartDrawer корректно рендерит товары, цены, кнопки.

### Шаг 1: Открыть главную страницу
```
Действие:   Открыть http://localhost:3000 в браузере
Ожидаем:    
  ✓ Страница загружается < 2 сек
  ✓ Видно меню сервисов (Services heading)
  ✓ Кнопка "Cart" в верхнем правом углу
  ✓ На кнопке Cart счётчик = 0
```

**Проверочный список:**
- [ ] Страница загружается без ошибок (Console нет 404/500)
- [ ] Видны все сервисы в каталоге (минимум 2: стандартный + express-code-review)
- [ ] Иконка Cart видна, счётчик пуст

---

### Шаг 2: Добавить первый сервис в корзину
```
Действие:   
  1. Нажать кнопку "Add to Cart" под первым сервисом
  2. Подождать 500ms
Ожидаем:    
  ✓ Кнопка становится неактивной (disabled state)
  ✓ На кнопке Cart счётчик меняется на 1
  ✓ Краткий Toast/уведомление "Added to cart" (если реализовано)
```

**Проверочный список:**
- [ ] Cart счётчик = 1
- [ ] Console нет ошибок (Network: POST /api/cart = 200)
- [ ] Кнопка добавления неактивна (уже в корзине)

---

### Шаг 3: Открыть CartDrawer
```
Действие:   Нажать на кнопку "Cart" (с счётчиком 1)
Ожидаем:    
  ✓ Справа выдвигается боковая панель (drawer)
  ✓ В панели видна услуга:
    - Название сервиса
    - Цена ($150.00 или $100.00)
    - Кнопка удаления (X или Delete)
  ✓ Внизу drawer: "Total: $150.00"
  ✓ Кнопка "Proceed to Booking" (или "Book Now")
```

**Проверочный список:**
- [ ] Drawer открывается слева-направо (или справа-налево, в зависимости от дизайна)
- [ ] Цена совпадает с сервисом (из `/api/catalog`)
- [ ] Total = сумма всех сервисов
- [ ] Кнопка "Proceed to Booking" видна и активна

---

### Шаг 4: Добавить второй сервис (дубликат — должно быть запрещено)
```
Действие:   
  1. Закрыть CartDrawer (нажать X или Escape)
  2. Попробовать нажать "Add to Cart" под тем же сервисом снова
Ожидаем:    
  ✓ Кнопка неактивна (disabled) или нет в наличии
  ✗ Если попытка через Console сделать POST /api/cart с тем же сервисом:
    Response: { error: "DUPLICATE_CART_ITEM" } (HTTP 400 или 409)
```

**Проверочный список:**
- [ ] Кнопка "Add to Cart" остаётся disabled для того же сервиса
- [ ] Console: POST /api/cart возвращает 400 с кодом DUPLICATE_CART_ITEM

---

### Шаг 5: Добавить другой сервис (express-code-review на 30 мин)
```
Действие:   Нажать "Add to Cart" под другим сервисом (express-code-review)
Ожидаем:    
  ✓ Cart счётчик меняется на 2
  ✓ Toast/уведомление "Added to cart"
```

**Проверочный список:**
- [ ] Cart счётчик = 2
- [ ] Console нет ошибок

---

### Шаг 6: Открыть CartDrawer и проверить содержимое
```
Действие:   Нажать "Cart"
Ожидаем:    
  ✓ Drawer показывает 2 сервиса в списке
  ✓ Total = сумма обоих ($150.00 + $100.00 = $250.00)
  ✓ Каждый сервис имеет кнопку удаления
```

**Проверочный список:**
- [ ] Оба сервиса видны в drawer
- [ ] Total правильный
- [ ] Каждый сервис можно удалить

---

### Шаг 7: Удалить сервис из корзины
```
Действие:   
  1. В CartDrawer нажать кнопку удаления (X) рядом со вторым сервисом
  2. Подождать 500ms
Ожидаем:    
  ✓ Сервис исчезает из drawer
  ✓ Cart счётчик меняется на 1
  ✓ Total обновляется на $150.00
```

**Проверочный список:**
- [ ] Второй сервис удалён из drawer
- [ ] Cart счётчик = 1
- [ ] Total = $150.00
- [ ] Console: DELETE /api/cart/[itemId] = 200

---

### Шаг 8: Очистить корзину полностью
```
Действие:   Удалить оставшийся сервис
Ожидаем:    
  ✓ Drawer пустой (сообщение "Your cart is empty" или пусто)
  ✓ Cart счётчик = 0
  ✓ Кнопка "Proceed to Booking" неактивна или исчезла
```

**Проверочный список:**
- [ ] Drawer пустой
- [ ] Cart счётчик = 0
- [ ] Drawer можно закрыть

## TC-WEB-02: Сетка Слотов 30 мин — Отображение, Недоступные Слоты, 30-мин Шаг

**Что проверяем:** Страница `/book` корректно отображает сетку доступных слотов, соблюдает 30-мин шаг, показывает занятые слоты как недоступные.

### Шаг 1: Добавить сервис в корзину (из TC-WEB-01)
```
Действие:   
  1. На главной странице нажать "Add to Cart" под express-code-review (30 мин)
  2. Проверить Cart счётчик = 1
```

**Проверочный список:**
- [ ] Cart счётчик = 1
- [ ] Сервис express-code-review в корзине (можно открыть CartDrawer и убедиться)

---

### Шаг 2: Перейти на страницу слотов
```
Действие:   
  1. Открыть CartDrawer
  2. Нажать "Proceed to Booking"
Ожидаем:    
  ✓ Перенаправление на страницу /book
  ✓ Загружается календарь или сетка слотов
  ✓ Видно расписание на день (текущий день или ближайший)
  ✓ Слоты распределены с шагом 30 минут:
    08:00, 08:30, 09:00, 09:30, 10:00, ...
```

**Проверочный список:**
- [ ] URL изменился на /book
- [ ] Видна сетка слотов
- [ ] Слоты идут по 30 минут (шаг = 30)
- [ ] Console нет ошибок (GET /api/availability = 200)

---

### Шаг 3: Проверить визуальное отличие занятых слотов
```
Действие:   Посмотреть на сетку слотов
Ожидаем:    
  ✓ Свободные слоты: обычная кнопка, фон светлый, курсор = pointer
  ✓ Занятые слоты: кнопка неактивна (disabled), фон серый, курсор = not-allowed
  ✓ Визуальное отличие ясное (контраст ≥ 4.5:1 по WCAG)
```

**Проверочный список:**
- [ ] Свободные слоты выглядят кликабельными
- [ ] Занятые слоты выглядят недоступными (серые или с крестом)
- [ ] Разница хорошо видна (не полагаемся только на цвет)

---

### Шаг 4: Выбрать свободный слот
```
Действие:   Нажать на первый свободный слот (например, 08:00 или 09:00)
Ожидаем:    
  ✓ Слот подсвечивается (другой цвет фона или рамка)
  ✓ Отображается информация:
    - Выбранный слот: "09:00 - 09:30" (если 30-мин услуга)
    - Дата
    - Итоговая цена
  ✓ Кнопка "Proceed to Checkout" становится активной
```

**Проверочный список:**
- [ ] Слот выбран и визуально отмечен
- [ ] Информация о слоте отображается корректно
- [ ] Кнопка "Proceed to Checkout" активна

---

### Шаг 5: Попробовать выбрать занятый слот (если есть в сетке)
```
Действие:   Нажать на один из серых (занятых) слотов
Ожидаем:    
  ✗ Слот не выбирается (остаётся выбранным предыдущий)
  ✗ Если в Console отправить POST /api/availability/hold с занятым слотом:
    Response: { error: "SLOT_UNAVAILABLE" } (HTTP 409)
```

**Проверочный список:**
- [ ] Нельзя выбрать занятый слот
- [ ] Текущее выделение не меняется

## TC-WEB-04: Обработка Конфликтов — Слот Занят, Ошибка "SLOT_UNAVAILABLE"

**Что проверяем:** Когда между выбором слота и отправкой заказа слот был занят другим пользователем, система показывает ошибку.

### Предусловие
```
Нужны два клиента одновременно (или имитировать в скрипте):
  1. Клиент A: Выбрал слот 09:00-09:30, начал заполнять форму
  2. Клиент B: Через API бронирует тот же слот 09:00-09:30
  3. Клиент A: Отправляет форму (слот уже занят)
```

### Шаг 1: Запустить скрипт-конфликт (или сделать руками)
```
Действие:   
  1. Открыть 2 окна браузера (или 2 браузера)
  2. В окне A: следовать TC-WEB-02 и TC-WEB-03 до шага заполнения формы
  3. В окне B (или скрипт): Запустить
     bash scripts/04-conflict.sh
     (это бронирует тот же слот, что выбран в окне A)
  4. В окне A: Нажать "Place Order"
Ожидаем:    
  ✓ Если слот занят:
    - Ошибка в браузере: "Slot is no longer available" или похожее
    - Перенаправления нет, форма остаётся с ошибкой
  ✓ Console: POST /api/orders = 409 или 400, error = "SLOT_UNAVAILABLE"
```

**Проверочный список:**
- [ ] Ошибка отображается в браузере
- [ ] Кнопка "Place Order" может быть нажата снова (после освобождения слота)
- [ ] Console показывает 409 или 400

---

### Шаг 2: Вернуться и выбрать другой слот
```
Действие:   
  1. Закрыть ошибку (если модал)
  2. Нажать кнопку "Back" или "Choose another slot"
  3. Выбрать другой слот (10:00-10:30)
  4. Заново отправить форму
Ожидаем:    
  ✓ Заказ успешно создан с новым слотом
  ✓ Перенаправление на успех-страницу
```

**Проверочный список:**
- [ ] Возможен откат и новый выбор слота
- [ ] Второй заказ создаётся с другим слотом
- [ ] Console: POST /api/orders = 201

## TC-WEB-05: Ошибки Валидации (Guard) — "DUPLICATE_CART_ITEM", "INVALID_DURATION", etc.

**Что проверяем:** Guard-ошибки при попытке добавить недопустимые товары отображаются в UI.

### Шаг 1: Попытка добавить дубликат (см. TC-WEB-01, шаг 4)
```
Действие:   Из Console выполнить:
  fetch('/api/cart', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ serviceId: '<SERVICE_ID>', duration: 60 })
  }).then(r => r.json()).then(console.log)
  
  (подставить реальный SERVICE_ID из `/api/catalog`)
Ожидаем:    
  ✓ Response: { error: "DUPLICATE_CART_ITEM" }
  ✓ HTTP 400 или 409
  ✓ Если UI слушает ошибку:
    - Toast или alert: "This service is already in your cart"
```

**Проверочный список:**
- [ ] API возвращает код ошибки DUPLICATE_CART_ITEM
- [ ] HTTP-статус 400 или 409
- [ ] Console нет серых ошибок (request должен завершиться)

---

### Шаг 2: Попытка выбрать недопустимую длительность слота
```
Действие:   Если услуга требует точную длительность (например, 30 мин):
  1. Открыть /book (слоты)
  2. Из Console попытаться забронировать слот на 25 или 45 минут:
  
  fetch('/api/availability/hold', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', 'Authorization': 'Bearer ' + localStorage.getItem('token') },
    body: JSON.stringify({ orderId: '<ORDER_ID>', slotStart: '2024-12-20T09:00:00Z', duration: 25 })
  }).then(r => r.json()).then(console.log)
  
Ожидаем:    
  ✗ Response: { error: "INVALID_DURATION" } или похожее
  ✗ HTTP 400
```

**Проверочный список:**
- [ ] API отклоняет неправильную длительность
- [ ] Console показывает ошибку
