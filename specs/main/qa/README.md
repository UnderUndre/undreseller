# specs/main/qa — App-Level Manual QA Suite

This folder holds the whole-app manual regression suite (ISO/IEC/IEEE 29119) that spans every feature wave (001 template, 002 cart+staff-bot, 003 booking template/RBAC, 004 release readiness): `legacy-audit-002.md` is the per-test-case verdict table for the old 002 checklists (VALID / UPDATED / SUPERSEDED / OBSOLETE — testers must not run stale expectations); `test-cases.md` defines the consolidated `TC-MAIN-NNN` suite re-including every surviving 002 case rewritten to current behavior plus cross-cutting cases (RBAC matrix, token rotation, feature-flag killswitch, four FSM track×payment combinations, waitlist, custom fields, i18n, zero-PII logs); `rtm-matrix.md` traces requirements (`FR-*`, `NFR-*`) to those cases with risk scoring and NFR evidence slots; `regression-suite.md` packages them into Smoke (P0 ≤15 min) / Sanity (P1 ≤45 min) / Full waves with environment prerequisites. Relationship to per-feature QA: 002 checklists (`specs/002-service-cart-and-staff-bot/checklists/`) are superseded exactly as ruled in `legacy-audit-002.md` (its scripts are still reusable as tooling); 004's own `qa/` folder (when it lands in `specs/004-release-readiness/`) covers the 004 feature stories in depth — this folder is the app-wide integration layer. How to combine: read `legacy-audit-002.md` first, run `regression-suite.md` waves using `test-cases.md` as the source of truth, pull feature-specific deep dives from the per-feature qa folders for any failed TC, and record evidence in the RTM `[PENDING]` cells.
