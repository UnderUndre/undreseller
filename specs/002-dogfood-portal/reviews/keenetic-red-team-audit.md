### ⚠️ Оставшиеся скрытые мины в спеке:

#### Мина №1. Арифметика памяти: «Парадокс Двойного Демо»
* Боевая Twenty CRM: **2.5 GB**
* Демо Twenty CRM: **еще 2.0–2.5 GB**
* Боевой таск-трекер: **1.5 GB**
* Демо Plane: **минимум 4.0 GB**
* Chatwoot: **3.5 GB**
* Authentik + Postgres + PgBouncer + Redis: **~5.5 GB**

**Итого:** Если запускать боевой стек **И** изолированные демо-песочницы на одной машине — суммарное потребление улетает за **$20\text{--}24\text{ GB RAM}$**! В лимит Hetzner CPX42 (16 GB) это **не влезет физически**, даже если выкинуть ядро Linux.  
*Решение:* На боевом сервере держи только прод. Демо-песочницы должны быть либо на отдельном инстансе, либо демо-режим для клиентов оформляется в виде интерактивного видеотура (Arcade / Supademo / Storylane), пока нет бюджета на второй VPS.

#### Мина №2. Исчезнувший Plane.so
Plane Community Edition — это распределенный монстр из 9–12 контейнеров, требующий $\ge 4\text{--}8\text{ GB RAM}$. Исключить Plane.so из единого 16GB хоста; использовать легковесный канбан внутри Twenty CRM.

## ЧАСТЬ 2. ХОСТИНГ НА ДОМАШНЕМ ПК ЧЕРЕЗ РОУТЕР KEENETIC (RED TEAM AUDIT)

```
[Клиент: США/ЕС] 
       │ ~100ms
       ▼
[Дешевый VPS: Hetzner]
       │
       │ ⚠️ УЗКОЕ ГОРЛО: Реверс-трафик через публичный интернет (~80-120ms)
       │ (Бытовой провайдер, серая маршрутизация, асимметричный канал)
       ▼
[Роутер Keenetic: Белый IP / NAT] ──► 🚨 ПРЯМОЙ ПРОБРОС ПОРТА В WAN (0.0.0.0/0)
       │
       ▼
[Домашний ПК: Docker]
       │
   [БОМБА ЗАМЕДЛЕННОГО ДЕЙСТВИЯ: Локалка 192.168.1.0/24, Smart TV, торренты, спящий режим]
```

### Векторы деанонимизации и компрометации:
1. **Shodan / Censys (Port Forwarding):** Сканеры находят открытый порт, выкачивают SSL-сертификат `underundre.com` или фавиконку и склеивают домашний Residential IP с доменом.
2. **SSRF и Out-of-Band (OOB) утечки:** Аватарки и ссылки в Chatwoot/Twenty CRM выкачиваются с домашнего интерфейса `eth0`, раскрывая IP в логах атакующего.
3. **Тайминг-атаки и джиттер:** Дельта TTFB $250\text{ ms}$ между статикой на VPS и динамикой на бэкенде выдает домашний хостинг.
4. **Утечки в HTTP-заголовках:** Заголовки `Location` (301/302), stack traces с локальными путями (`C:\Users\...`) и SMTP `Received:` заголовки.
5. **MTU / TCP Fingerprinting:** PPPoE/L2TP MTU (1492/1460) vs дата-центровый 1500.

## ЧАСТЬ 3. ПРАВИЛЬНЫЙ АРХИТЕКТУРНЫЙ ПАТЧ: ZERO-OPEN-PORTS (CLOUDFLARED)

```
[Клиент] 
   │
   ▼
[Cloudflare Edge (WAF, SSL, DDoS protection, CDN)]
   │
   │ 🔒 Зашифрованный туннель (Strict Outbound Only, порты ЗАКРЫТЫ)
   ▼
[Домашний ПК / Сервер: cloudflared daemon]
   │
[Docker Compose (Изолированная сеть bridge, no host network)]
```

### Регламент:
1. **Запрет Port Forwarding на роутере:** Все входящие порты закрыты наглухо.
2. **Cloudflare Tunnel (`cloudflared`):** Исходящее шифрованное соединение QUIC/HTTP2 до Cloudflare Edge.
3. **Изоляция сети Docker:** `driver: bridge`, спящий режим отключен (`powercfg -h off`).
