# UAT Scenarios: 007-code-review-fixes

> QA ищет баги расхождения со спекой; UAT проверяет бизнес-ценность. Разные вопросы.

## UAT-001: Владелец разворачивает инстанс с чистого листа — безопасность по умолчанию

- **Target Persona**: Владелец white-label инстанса (OWNER, самообслуживание)
- **Business Goal**: Забытые env-секреты не создают молчаливых дыр — система явно отказывает и подсказывает, что настроить, вместо работы с публично известными ключами
- **Success Criteria**:
  1. Деплой без `STAFF_WEBHOOK_SECRET`/`ADMIN_TOKEN` → reschedule-оффер даёт внятный 503, а не «работает с дефолтным ключом»
  2. Логи доставки не создают иллюзии псевдонимизации (`UNHASHED` виден явно)
  3. Ни одна ссылка/подпись в системе не вычисляется секретом из исходного кода
- **Validation Steps**: 1) поднять инстанс с частичным env; 2) попытаться отправить reschedule-оффер; 3) инспекция delivery-лога; 4) grep-пруф (SC-001)
- **Business Sign-off**: [PENDING]

## UAT-002: Оператор не теряет деньги и время на «тихих» операциях

- **Target Persona**: Оператор/диспетчер (OPERATOR) + владелец (финансовый контроль)
- **Business Goal**: Каждое действие либо честно выполняется, либо честно отказывает; расхождение суммы платежа останавливает автопилот и зовёт человека, а не списывает сток молча
- **Success Criteria**:
  1. RESCHEDULE из админки даёт понятный отказ (501) вместо «вроде успешно» — оператор знает, что перенос делается через бота
  2. Недоплата/валютный mismatch по любому провайдеру → заказ в ручной резолюции, сток не списан, refund-request создан
  3. Ни один существующий рабочий сценарий (оплата, подтверждение, отмена) не изменил поведения
- **Validation Steps**: 1) попытка RESCHEDULE через API; 2) прогон mismatch-платежа (TC-007-009); 3) полный smoke-прогон бронирования (regression-suite §Smoke)
- **Business Sign-off**: [PENDING]
