## Найденные и исправленные живые баги (int-тесты их не ловили — только реальный рендер)

1. **CRITICAL (UI-500)**: `/book/[slug]` — Server Component передавал **функцию-проп** (`onBooked`) в клиентский `SlotGrid` → «Functions cannot be passed directly to Client Components» → 500 на каждой странице услуги. **Фикс**: навигация на confirmation перенесена внутрь `SlotGrid` (onBooked опционален), из page.tsx проп удалён.
2. **HIGH (UX)**: `AcknowledgeClient` — авто-POST на маунте; React StrictMode в dev дважды зажигает effect → второй конкурентный CAS получает 409 CONFLICT → пользователю показывалось «Failed: CONFLICT» при УСПЕШНОМ акке (v1→v2 в DB). **Фикс**: 409 CONFLICT трактуется как успех (ack записан конкурирующим дублем).
3. **MEDIUM (спека-маунт)**: `CalendarFeedLink` не был подключён к /admin Resources (компонент существовал, маунт-слот отсутствовал) + `beforeDocumentControls` не получает `id` в пропсах — guard прятал компонент. **Фикс**: слот `edit.beforeDocumentControls` + id читается из URL-path edit-view.
4. **ENV (не баг)**: Cyrillic через shell-curl пишется кракозябрами (Windows-кодировка) — seed через `--data-binary @file` (UTF-8).

## Замечания по инфраструктуре QA (не баги приложения)

- IAB-клики (`playwright.click`/dom_cua) флеймят на React-кнопках (то срабатывают, то нет) — надёжный путь: page-context `evaluate(() => btn.click())`. На это ушло 3 ложных «не работает».
- window.fetch в Next-странице кэширует одинаковые GET (ротация выглядела нерабочей) — проверять с `cache: 'no-store'` или curl.
