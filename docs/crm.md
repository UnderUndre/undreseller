### 🔍 2. Технический аудит Twenty CRM (`twentyhq/twenty`): Что внутри этой трубы?

Я прогнал Twenty CRM через диагностику. Штука на самом деле **очень бодрая**, но со своими прокладками, которые надо знать.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    ТЕХНИЧЕСКИЙ СРЕЗ TWENTY CRM (v2.x)                       │
├───────────────────┬─────────────────────────────────────────────────────────┤
│ СТЕК              │ TypeScript, NestJS, PostgreSQL, Redis, BullMQ, React    │
│ АРХИТЕКТУРА       │ Dynamic Object System (в стиле Salesforce), Metadata    │
│ API               │ REST + GraphQL + Webhooks + Нативный MCP Server         │
│ ЛИЦЕНЗИЯ          │ AGPLv3 (ядро) + MIT (SDK/UI) + Application Exception    │
└───────────────────┴─────────────────────────────────────────────────────────┘
```

#### ✅ Где течёт гладко (Плюсы)

* **Архитектурный кайф (Salesforce на современный лад):** Это буквально современный клон логики Salesforce, но переписанный на человеческом TypeScript. Объекты и поля можно объявлять прямо кодом через `twenty-sdk` (`defineObject`, `FieldType`) и коммитить в Git. Для NACE 62.01 — идеальный материальный артефакт!
* **Нативный MCP-сервер:** Claude / Cursor могут напрямую через Model Context Protocol дергать данные, ставить задачи и создавать кастомные связи. Для твоего AI-пайплайна — сказка.
* **Идеальный стык с n8n:** Полноценный GraphQL/REST API и вебхуки на любое изменение сущности. Лиды из n8n залетают со свистом.

#### ⚠️ Где может сорвать резьбу (Подводные камни и косяки)

* **Жрёт память как не в себя:** Это не легковесный Go-бинарник. Связка NestJS + Postgres + Redis + BullMQ-воркеры + фронт в Docker требует **минимум 8 ГБ RAM** на VPS. На дешёвом сервере за €5 на Hetzner он просто ляжет от OOM (Out of Memory). Нужен нормальный инстанс (Hetzner CX32 / CPX31 от €10-15/мес).
* **Сырость миграций между версиями:** Двадцатка пилится бешеными темпами. При `docker compose pull` и накатывании мажорного апдейта база иногда встает раком, если были кастомные схемы. Клиент сам это не обновит — нужен твой Retainer.
* **Капризный UI на объемах:** Если залить туда больше 1000–2000 активных сделок, канбан-доска в браузере начинает ощутимо подлагивать.
* **Лицензионная ловушка (AGPLv3):** Ядро под AGPLv3. Это значит: **ни в коем случае не форкать и не переписывать исходники самого Twenty под клиента**, иначе по лицензии ты обязан открыть весь код. Кастомизацию делать **строго** через официальный SDK (`packages/twenty-apps`), API или внешние n8n-воркфлоу.

### 🧰 Разбор кандидатов: Где какая резьба нарезана?

#### 1. EspoCRM — Главный конкурент Twenty (Немецкий дизель)

Если тебе нужна **пуленепробиваемая надёжность**, то EspoCRM — это автомат Калашникова в мире опенсорс CRM.

* **Плюсы:**
  * **Жрёт копейки:** Вся пачка в Docker (Nginx + PHP-FPM + MySQL + Cron) жрёт **меньше 1.5 ГБ RAM**. Легко встает на сервак за €4-6/мес на Hetzner.
  * **Права доступа (ACL/RBAC):** Они там вылизаны за 10 лет до совершенства. Можно настроить: «Менеджер видит только свои сделки, РОП видит отдел, а бухгалтер видит только выставленные счета». В Twenty до такой гранулярности ещё пилить и пилить.
  * **No-Code Layout & Entity Manager:** Кастомные поля, воронки, связи 1:N и N:M настраиваются кликами в админке без написания кода и применяются на лету без перезапуска контейнеров.
* **Где засор:**
  * **Стек — PHP 8:** Для тебя, как TS-разработчика, писать туда кастомные бэкенд-хуки — это шаг назад в прошлое. Фронтенд на старом Backbone.js (хоть и быстрый, но расширять UI кодом неприятно).
  * **Нет нативного MCP:** Прикручивать AI придётся классически — через n8n вебхуки и REST API.

---

#### 2. Frappe CRM — Новый легковесный хипстер

Выпущен ребятами из Frappe / ERPNext как отдельная, супер-чистая CRM.

* **Плюсы:** Красивый минималистичный UI (в стиле modern SaaS), встроенные воронки, лид-трекинг, звонки и почта. Не такой тяжелый, как целый ERPNext.
* **Где засор:** Стек **Python + Frappe Framework**. У Frappe своя собственная замкнутая экосистема (DocTypes, Bench CLI, Hooks). Чтобы нормально кастомизировать — надо учить их внутренний "монастырский устав". Это забивает тебе голову лишним стеком.

---

#### 3. SuiteCRM — «Монстр Франкенштейна» (Категорически НЕТ)

Это прямой форк SugarCRM. По логике он на 100% повторяет классический старый Salesforce.

* **Где засор:** **Ни в коем случае не суй туда пальцы — оторвёт к хуям.** Миллионы строк легаси-PHP, кривые шаблоны, админка из 2005 года. Клиент зайдёт туда, испугается и потребует деньги назад по эскроу Upwork. Забудь как страшный сон.

---

#### 4. Directus / NocoBase — Конструктор «Сделай Сам» на TypeScript

Directus — это не CRM, а готовый бэкенд с красивой админкой поверх твоей PostgreSQL.

* **Плюсы:** 100% родной TypeScript, смешное потребление RAM (500 МБ), идеальный GraphQL/REST, отличная ролевая модель.
* **Где засор:** В нём **нет готовой логики CRM** из коробки (нет канбана сделок с drag-and-drop суммами, нет встроенного трекинга email-переписки, нет сущностей Leads/Deals). Тебе придётся собирать это руками. Это противоречит принципу «Готового Шланга» и убьёт твой 3–5 дневный таймбокс.
